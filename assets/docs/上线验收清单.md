# 上线验收清单（30 条 · 不勾完别对外发链接）

> 立这份清单的原因，是一句最痛的经验：「AI 做得很快，但是我没有足够的时间去验收，也不知道功能完不完整，有没有 bug。」
> **骨架负责快，验收负责不翻车。** 全栈 SOP 里速度已经不是瓶颈，验收才是。
> 用法：上线前逐条勾，填「通过 / 不通过 / 不适用 + 证据」；任何「不通过」先修再发 P8 提示词让 AI 复核。

## A. 功能与交互（5 条）

- [ ] A1 首屏一句话说清价值，主输入框 + 生成按钮 + 结果区齐备
- [ ] A2 加载中 / 成功 / 失败 / 空状态 / 无权限，五种状态都有明确反馈
- [ ] A3 所有外部输入经 zod 校验，超长、空值、特殊字符不会打崩接口
- [ ] A4 刷新页面后，生成记录仍在（数据库链路通）
- [ ] A5 结果可下载/复制，签名 URL 带过期时间

## B. 鉴权（4 条）

- [ ] B1 注册 / 登录 / 退出全流程可用（本地 + 线上各验一遍）
- [ ] B2 未登录访问 `/api/<topic>/generate` 返回 **401**，前端有「先登录」引导
- [ ] B3 Clerk 后台已配置本地与线上两套 Allowed Origins / 回调地址
- [ ] B4 `service_role key` 只在服务端使用，未出现在任何 `NEXT_PUBLIC_` 变量

## C. 支付与点数（5 条）★ 最容易翻车

- [ ] C1 webhook 用 **raw body** 验签，错误签名返回 4xx 且点数不变
- [ ] C2 **同一条 webhook 重放两次，点数只加一次**（`orders.provider_event_id` 唯一）
- [ ] C3 「写订单 + 加点数」在同一个数据库事务里
- [ ] C4 点数流程是「冻结 → 生成成功才扣 → 失败回滚」，失败绝不扣点
- [ ] C5 全程测试模式/沙箱金额；线上回调 URL 与 env 中的密钥一致

## D. 引擎与 Fallback（5 条）★ 最贵的教训

- [ ] D1 所有 AI 调用走 `runWithFallback()`，页面/业务代码里无厂商 SDK 直连
- [ ] D2 降级链至少两级 + **末尾 `mock`**；主引擎 key 改错仍能给出结果或明确提示
- [ ] D3 15s 超时生效（模拟挂起请求验证），无白屏、无无限转圈
- [ ] D4 失败写 `generations.status = fallback / failed` 并留日志，无静默 catch
- [ ] D5 **未使用任何非官方端点、个人账号 session**（真实翻车案例）

## E. 成本与性能（4 条）

- [ ] E1 `estimateCost()` 成本阀生效，超 `MAX_COST_PER_CALL` 直接拒绝
- [ ] E2 后台能查到「昨日总引擎成本 / 单次成本 / 调用次数」
- [ ] E3 完成单位经济测算：`单次成本 × 调用量 ≤ 定价`，结论写在 README
- [ ] E4 首字/首图与 **P95 延迟**达到验收阈值（默认 P95 < 3s，按场景调整）；避免 >5s 那种留存崩塌

## F. 数据与隐私（3 条）

- [ ] F1 仓库无 `.env.local`、无密钥、无用户数据；`.gitignore` 齐全
- [ ] F2 `profiles` 有 RLS 或等价服务端保护，用户不能改他人点数
- [ ] F3 用户数据、AI 生成内容标识、版权与目标市场合规要求已自行核实

## G. SEO 与内容（2 条）

- [ ] G1 每页唯一 title / description / canonical，带结构化数据，`sitemap.xml` 可访问
- [ ] G2 **无空壳页、无他人品牌词、无抢注域名**（蹭品牌词被停解析的教训）；宣称口径与实际能力一致

## H. 部署与回滚（2 条）

- [ ] H1 `pnpm typecheck && pnpm lint && pnpm test && pnpm build` **四条全绿**
- [ ] H2 保留上一个可部署版本，可一键回退；线上环境变量（Production / Preview）齐全
