# 新项目复用清单（复制骨架后改 8 个地方 · 15 分钟自检）

> 用法：每开一个新项目就复制本文件一份，改完打勾再开工。**只改这 8 处，其余一律不动。**
> 判据：如果你在第 3 个项目还要重新纠结「用哪个登录方案 / 表怎么建 / 支付回调怎么写」，说明骨架没钉死，回去改 `starter/SPEC.md`，而不是在项目里另起炉灶。

---

## 复制命令

```bash
cp -r 全栈铲子SOP/starter my-new-app
cp 全栈铲子SOP/templates/新项目复用清单.md my-new-app/复用清单.md
cd my-new-app
cp .env.example .env.local
```

---

## 必改 8 处

| # | 改哪里 | 改成什么 | ☐ |
|---|---|---|---|
| 1 | `src/apps/<topic>/` | 目录名换成英文短词（会进 URL 与数据库值），只保留 `page.tsx` + `route.ts` 骨架 | ☐ |
| 2 | `.env.local` | `NEXT_PUBLIC_APP_NAME`、`NEXT_PUBLIC_APP_URL`、`PRIMARY_ADAPTER`、`SECONDARY_ADAPTER`、`MAX_COST_PER_CALL` | ☐ |
| 3 | `README.md` | 一句话产品说明 + 怎么跑 + 怎么验（三行就够） | ☐ |
| 4 | `src/content/` | 本次文案；`core/ui` 的主题 CSS 变量（主色/圆角），**不改组件实现** | ☐ |
| 5 | `src/adapters/index.ts` | 降级链顺序，末尾**永远保留 `mock`** | ☐ |
| 6 | 支付后台 | 新建一个测试商品/价格，把新的 `BILLING_PRODUCT_ID` 与 webhook 密钥填进 env | ☐ |
| 7 | `SITE_URL` / metadata / sitemap | 换成新域名；title、description、OG 图 | ☐ |
| 8 | `SPEC.md` | **不改内容**，只在版本号旁注明「本项目基于 vX.Y」 | ☐ |

> ⚠️ 第 8 条最容易做错：**SPEC 是骨架规格，不是项目说明**。项目相关的东西写进 `README.md` 和 `apps/`，别往 SPEC 里塞。只有「下个项目还能用的通用能力」才回写 SPEC 并升版本。
