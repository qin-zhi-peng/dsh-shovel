# 第一次跑通 · 手把手（照着敲就行）

> 目标：从一台空电脑 → 本地 `http://localhost:3000` 能跑通「登录 → 扣点 → 生成 → 展示」→ 线上可访问。
> 全程不需要你写代码：`starter/` 是骨架规格，代码由 AI Coding 工具按 `SPEC.md` 和提示词生成。
> **这一步只做一次**；以后每个新项目直接从「§5 每个新项目」开始。

---

## Step 0 · 装工具（约 15 分钟）

```bash
# 1) Node.js：需要 20 以上（本环境是 22）
node -v
# 若没有或版本低：去 nodejs.org 装 LTS，或用 nvm：
#   nvm install 22 && nvm use 22

# 2) pnpm（Node 自带 corepack）
corepack enable
corepack prepare pnpm@latest --activate
pnpm -v

# 3) Git + GitHub 账号（部署要用）
git --version
git config --global user.name  "你的名字"
git config --global user.email "你的邮箱"
```

再装一个能跑 AI Coding 的编辑器/工具（任选其一，按你自己的习惯）：Cursor、Claude Code、CodeBuddy，或任何支持「把整个项目目录作为上下文」的 AI 编程工具。**关键能力**：能把 `SPEC.md` 和提示词整段发给它、让它直接改你本地文件。

---

## Step 1 · 注册九层账号（约 40 分钟，一次搞定）

按顺序注册，每注册一个就把拿到的值立刻填进 `.env.local`。**这些账号以后所有项目复用，是复利的起点。**

| 顺序 | 服务 | 去哪 | 要拿什么 | 填到 `.env.local` 哪一行 |
|---|---|---|---|---|
| 1 | GitHub | github.com | 一个空仓库 | —（用来 `git push`） |
| 2 | Vercel | vercel.com，用 GitHub 登录 | 导入仓库的权限 | —（自动部署） |
| 3 | Supabase | supabase.com → New Project | Project URL、anon key、**service_role key** | `SUPABASE_URL` / `SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY` |
| 4 | Clerk | clerk.com → 建 Application | Publishable key、Secret key | `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` / `CLERK_SECRET_KEY` |
| 5 | 支付 | Lemon Squeezy 或 Creem（MoR，个人主体更友好）；有海外主体再选 Stripe | API key、Webhook secret、Store/Product ID | `BILLING_API_KEY` / `BILLING_WEBHOOK_SECRET` / `BILLING_PRODUCT_ID` |
| 6 | AI 引擎 | OpenRouter（文本）/ Replicate 或 Fal（图像音视频） | API key | `OPENROUTER_API_KEY` / `REPLICATE_API_TOKEN` |
| 7 | R2（可后补） | Cloudflare Dashboard → R2 | Account ID、Access Key、Bucket 名 | `R2_*` |
| 8 | 域名（可后补） | Namecheap / Cloudflare Registrar | 一个自己的域名 | —（Vercel 里绑定） |

⚠️ 三条纪律（写进 `.gitignore`）：
- `.env.local` **绝不提交**到 Git，仓库里只放 `.env.example`。
- `service_role key`、支付密钥、AI key **只能放服务端**；任何 `NEXT_PUBLIC_` 开头的变量都是浏览器可见的。
- 本地 / 预览 / 生产用**三套 key**，服务商后台的回调地址也要配三套。

---

## Step 2 · 复制骨架并跑通占位页（约 10 分钟）

> 下面的复制命令在 `/workspace` 目录下执行；若已 `cd` 进方案包目录，去掉路径里的 `全栈铲子SOP/` 即可。

```bash
cp -r 全栈铲子SOP/starter my-first-app
cd my-first-app
cp .env.example .env.local        # 按 Step 1 填好；AI key 可以先空着
pnpm install
pnpm dev                          # 打开 http://localhost:3000
```

**这一步刻意不接任何真 AI 引擎**：`adapters/mock.ts` 会用假数据把整条链路跑通。看到下面四件事全绿，说明骨架是健康的：

- [ ] 页面能打开、样式正常
- [ ] 能用测试账号登录 / 退出
- [ ] 点「生成」，`mock` 返回结果，点数正确 -1
- [ ] 刷新页面，生成记录还在（数据库通了）

> 若 `pnpm dev` 起不来，先跳到文末「报错速查」。**先把 mock 跑通再接真引擎**，这是小白最容易省掉、也最不该省的一步。

---

## Step 3 · 让 AI 按 SPEC 生成你的第一个产品（约 30–60 分钟）

打开 AI Coding 工具，把这三样一次性喂给它（顺序别反）：

1. `starter/SPEC.md` 全文 —— 「这是硬约束，任何生成都不得违反」
2. `starter/prompts/复用提示词包.md` 里的 **P0 总指令**
3. **P1 新项目生成**，把里面的 `【主题】`/`【引擎】` 换成你这次要做的东西

然后只提一个要求，别一次让它干完所有事：

> 先只做「一个落地页 + 一个生成接口 + 一个 adapter」，用 `mock` 跑通。登录、支付暂时不要动。

**验收**：`core/` 目录一个文件都没被改；改动只落在 `apps/<topic>/` 和 `adapters/`。如果 AI 动了 `core/`，让它回滚——骨架被改一次，复利就断一次。

---

## Step 4 · 逐条接通四件套（每条跑完验一次）

按提示词包顺序，**一次一条**，每条都用「验收点」当场确认：

| 提示词 | 接通什么 | 当场验收 |
|---|---|---|
| P2 | 登录（Clerk） | 线上/本地都能登录；未登录访问生成接口返回 401 |
| P3 | 数据库（Supabase 四张表） | Supabase 后台能看到 `profiles/orders/generations` 新行 |
| P4 | 支付 + 点数 | **把同一条 webhook 重放两次，点数只加一次**（幂等） |
| P5 | 真 AI 引擎 + Fallback | 断网/填错 key 时走 `mock` 并给出明确提示，不白屏、不扣点 |

支付回调最容易翻车，三个必查：
- 服务商后台的 Webhook URL 指向 `https://<你的域名>/api/billing/webhook`（本地调试用内网穿透或测试模式）。
- 验签必须用**原始请求体**（raw body），不要先被 JSON 中间件解析掉。
- `orders.provider_event_id` 唯一约束 + 事务里「写订单 + 加点数」，二者缺一不可。

---

## Step 5 · 部署上线（约 10 分钟）

```bash
# 本地先构建一次，能把 80% 的部署失败提前拦下来
pnpm build

git init && git add . && git commit -m "init: from fullstack shovel SOP"
git remote add origin https://github.com/<你>/<仓库>.git
git push -u origin main
```

然后在各后台补齐**线上**配置：

- [ ] Vercel：导入仓库 → 把 `.env.local` 里的所有变量逐条粘进 Project Settings → Environment Variables（Production / Preview 分开）→ Redeploy
- [ ] Clerk：把生产域名加入 Allowed Origins / 回调地址
- [ ] 支付：Webhook URL 换成生产域名，确认签名密钥与 Vercel 里的一致
- [ ] Supabase：确认生产项目与本地不是同一个（别把测试数据带上线）
- [ ] 域名：Vercel → Domains 绑定，等 DNS 生效
- [ ] 打开 `https://<你的域名>`，把 Step 2 的四件事再走一遍

---

## Step 6 · 过验收清单 + 回写骨架

- 逐条勾 `templates/上线验收清单.md`（30 条），不勾完别对外发链接。
- 问一句：**这次写的哪段代码下个项目还能用？** 能就复制回 `starter/`，把 `SPEC.md` 版本号 +0.1，并在 `templates/新项目复用清单.md` 里记一笔。
- 记录「复制骨架 → 首个可访问页面」的耗时。健康曲线：第 1 个 1 天 → 第 2 个 3 小时 → 第 3 个 1 小时内。

## 每个新项目（跳过 Step 0–1，只要 5 步）

```bash
cp -r 全栈铲子SOP/starter my-new-app && cd my-new-app
# ① 按 templates/新项目复用清单.md 改 8 个地方
# ② 把 SPEC + P0 + P1 发给 AI，只改 apps/ 与 adapters/
# ③ pnpm i && pnpm dev，mock 跑通
# ④ P2~P5 按需接通 + 过上线验收清单
# ⑤ git push 上线，回写 starter
```

## 报错速查

| 现象 | 原因 | 怎么修 |
|---|---|---|
| `pnpm: command not found` | corepack 没启用 | `corepack enable && corepack prepare pnpm@latest --activate` |
| `node -v` < 20 / Next.js 装不上 | Node 太老 | 装 Node 22 LTS，重开终端 |
| `Error: Port 3000 is in use` | 端口占用 | `pnpm dev -p 3001`，或 `kill` 掉旧进程 |
| 页面 500、控制台提示 env undefined | `.env.local` 没填或名字写错 | 对照 `.env.example` 逐行核；改完**重启** dev server |
| 浏览器里能读到密钥 | 误用 `NEXT_PUBLIC_` 前缀 | 服务端密钥去掉该前缀，只在 server 代码引用 |
| 登录后跳回报错页 | 回调 URL 没配 | Clerk 后台补本地 + 线上两套 Allowed Origins / Redirect URL |
| Webhook 400 / 签名失败 | 密钥不一致或 body 被解析 | 核对 webhook secret；用 raw body 验签 |
| 支付成功但点数加了两次 | 没做幂等 | `orders.provider_event_id` 加 unique，事务内先查再写 |
| AI 一直超时 / 白屏 | 没有 Fallback 链 | 走 `runWithFallback`，末尾必须挂 `mockAdapter` |
| 生成成功但用户被扣了两次点 | 扣点没用事务 | 冻结 → 生成 → 成功才扣；失败回滚 |
| 图片外链 403 | R2 权限 / 签名 URL 过期 | 用签名 URL 并设合理过期；别把 bucket 设成全公开还放敏感内容 |
| Vercel 构建失败 | 本地没先 build | 本地 `pnpm build` 通过再 push；看 Build Logs 第一行真实报错 |
| 线上能用、本地不能用（或反之） | 只配了一套 key/回调 | 三套环境 key 与回调 URL 分开配 |
