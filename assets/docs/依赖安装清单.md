# 依赖安装清单（复制命令即可，不用手抄版本号）

> 对应 `SPEC.md` §1 钉死的九层选型。用 `pnpm add` 让包管理器自动取当期稳定版，避免写死版本导致过期。
> **加任何新依赖前先问一句：这能不能用现有包实现？** 依赖越少，骨架越稳（SPEC §0 铁律 5）。

```bash
# 0) 先有项目骨架
cp -r 全栈铲子SOP/starter my-app && cd my-app
pnpm init

# 1) 框架与语言（Next.js App Router + React + TypeScript）
pnpm add next react react-dom
pnpm add -D typescript @types/node @types/react @types/react-dom

# 2) 样式与 UI（Tailwind + shadcn 基础组件）
pnpm add tailwindcss @tailwindcss/postcss postcss clsx tailwind-merge lucide-react
pnpm dlx shadcn@latest init          # 按提示选主题；生成的组件放 src/core/ui/

# 3) 登录
pnpm add @clerk/nextjs

# 4) 数据库
pnpm add @supabase/supabase-js

# 5) 输入校验
pnpm add zod

# 6) 支付（按你选的服务商装其一即可；也可以只用 fetch 调 REST，不装 SDK）
#    Stripe:        pnpm add stripe
#    Lemon Squeezy: pnpm add @lemonsqueezy/lemonsqueezy.js
#    Creem:         按官方当期文档，或直接用 fetch

# 7) 文件存储（R2 兼容 S3 协议）
pnpm add @aws-sdk/client-s3 @aws-sdk/s3-request-presigner

# 8) 测试与规范
pnpm add -D vitest eslint eslint-config-next prettier
```

## 常用脚本（写进 package.json 的 scripts）

```json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "lint": "next lint",
    "typecheck": "tsc --noEmit",
    "test": "vitest run"
  }
}
```

**上线前必跑三条**（这也是 `SPEC.md` §7 完成定义的一部分）：

```bash
pnpm typecheck && pnpm lint && pnpm test && pnpm build
```

## 选型的「不装」清单

| 别装 | 原因 |
|---|---|
| 额外的状态管理库 | 服务端组件 + URL 状态够用，别给骨架加复杂度 |
| 多个 UI 组件库混用 | 全站只认 shadcn 一套，否则主题会分裂 |
| 自己封装的 HTTP 客户端 | 原生 `fetch` + `core/fallback` 的超时重试即可 |
| 各类「一键全栈框架」 | 与固定骨架冲突，等于换骨架、复利归零 |
| 未经批准的 AI SDK | 各厂商 SDK 必须被 `adapters/` 包一层（SPEC §3） |

---

*包名与安装方式以各官方当期文档为准；`pnpm dlx shadcn@latest init` 等初始化命令的交互选项可能随版本变化。*
