# 成本、Fallback 与六条红线

> 最贵的一课：**「成本优化是产品决策，不是运维事项」**。
> 有工具产品月访问 60 万+、付费率却只有 0.03%，Token + 带宽成本一度把它做成负收入；把站点从 Vercel 迁到 Cloudflare 后「每月省了几万块」，再做完成本优化才做到营收平衡。
> 这份文件的作用：让这副骨架在**上线之前**就把成本、降级、合规算清楚。

---

## 1. 免费起步策略（先别花钱）

| 层 | 免费做法 | 什么时候才该花钱 |
|---|---|---|
| 部署 | Vercel Hobby（注意免费档的商用限制） | 有稳定流量 / 需要商用条款时，再评估 Cloudflare 等方案 |
| 数据库 | Supabase 免费项目 | 数据量、并发或休眠策略不满足时 |
| 登录 | Clerk 免费额度 | 超出 MAU 额度 |
| 支付 | MoR 类服务通常无月费、按成交抽成 | 天然是「有收入才付费」，不必预付 |
| AI 引擎 | 先用 `mockAdapter` 跑通全流程，再用小额充值接真引擎 | 验证出有人愿意用/愿意付，再放量 |
| 文件 | R2 免费额度 | 超出后按量计费 |
| 模板/UI | shadcn/ui + Tailwind（免费） | 确定要长期做、且商业模板能省下明显时间时再买 |
| 域名 | 只买**一个**自己品牌的中性域名 | 绝不囤域名、绝不抢注他人品牌词 |

> 顺序建议：**mock 跑通 → 小额真实调用 → 有人付费 → 放量**。「流量 ≠ 生意」是反复验证过的：有目录站全年上千万访问，广告收入也才 1.2 万美金，别先为想象中的流量付账单。

## 2. 单位经济：定价前必算的一个式子

```
单次成本 = 引擎调用费 + 存储/带宽 + 函数计算 + 支付通道抽成
毛利/单  = 售价 − 单次成本
成立条件 = 付费转化率 × 人均调用次数 × 毛利/单  >  获客成本
```

`templates/成本测算表.csv` 就是这张表的可填写版。填法是：

| 字段 | 从哪来 | 示例（示意数字，非报价） |
|---|---|---|
| 引擎单价 | 服务商价格页 | 0.02 元/次 |
| 平均调用次数/次任务 | `generations` 表统计 | 1.3 次（含重试） |
| 存储+带宽/单 | 结果文件大小 × 平均下载 | 0.01 元 |
| 支付抽成 | 通道费率 × 售价 | 售价的 5% |
| **单次成本合计** | 以上相加 | ≈ 0.04 元 |
| 定价 | 你定 | 1 元 / 10 点 |
| 付费率 | 埋点实测（别猜） | 见过低至 **0.03%** 的案例 |
| 结论 | 算式 | 若付费率 <1%，先别放量 |

**三个必须落进代码的动作**（否则算不出来）：

1. 每次生成往 `generations` 写 `adapter / cost_yuan / latency_ms / status`（建表 SQL 见 `01_全栈开发SOP.md` §4）。
2. `estimateCost()` 在调用前跑，超过 `MAX_COST_PER_CALL` 直接拒绝 —— **Token 是钱，上下文是金**。
3. 结果文件走 CDN 缓存 + 签名 URL 设过期，别让源站反复吐大文件。

## 3. Fallback：所有外部依赖都要有降级路径，没有例外

工程实践里把这条写成原则：「生产级 Agent 必须对所有外部依赖做 Fallback。没有例外。」起因是有音乐生成工具依赖非官方端点与个人账号 session，引擎一改版产品直接停摆——「**开源的是壳与账务系统，拿不走的永远是引擎**」。

骨架里的实现方式：`src/core/fallback/chain.ts` 的 `runWithFallback()`（见 `01_全栈开发SOP.md` §3），四件事缺一不可：

| # | 机制 | 验收方式 |
|---|---|---|
| 1 | 至少两级真引擎 + 末尾 `mockAdapter` 兜底 | 把主引擎 key 改错，页面仍给出明确结果或明确提示 |
| 2 | 15s 超时（AbortSignal） | 模拟挂起请求，不白屏、不无限转圈 |
| 3 | 失败留痕（`status = fallback`） | `generations` 表能查到降级记录 |
| 4 | 失败不扣点、并显式报错 | 断网时点数不变，用户看到可理解的提示 |

`templates/依赖与Fallback表.csv` 每接一个外部能力就填一行：**依赖对象｜拿它做什么｜是否官方接口/SLA｜它变更/收费/下场自做时的替代方案｜风险等级｜触发预案**。

再问自己四句（依赖盘点四问）：
1. 用户完成核心价值，是否需要离开我们的产品？（有封面工具卡在平台审核，价值链断在最后一公里）
2. 这个能力有可谈判的合约或**官方**接口吗？（很多工具类的答案就是「没有」）
3. 如果平台明天自己做这个功能，我们还剩什么？（有建站工具被模型内化后停更）
4. 依赖中断，降级路径是什么？

## 4. 六条红线（「不学」清单的技术版）

| # | 红线 | 代价 |
|---|---|---|
| 1 | **不蹭品牌词、不抢注域名** | 有蹭品牌词的域名被禁止解析，还引发「虚假宣传」舆论反噬 |
| 2 | **不依赖非官方端点 / 个人账号 session** | 有音乐工具引擎一改版整体停摆，域名后来甚至变成博彩站 |
| 3 | **不把产品做成「模型再强一代就没用了」的临时补丁** | 「一句话生成网页」被模型内化，定位尴尬、停止迭代 |
| 4 | **不无验收地快速铺量** | 「AI 做得很快，但没时间验收，不知道功能完不完整、有没有 bug」→ 所以本包有 30 条上线验收清单 |
| 5 | **不只盯访问量** | 有工具产品 60 万+ 月访问 / 0.03% 付费率；另一款 10 万/天几乎不转化 |
| 6 | **不每月换骨架** | 骨架一换，前面所有项目的沉淀归零；唯一产生复利的动作是把骨架本身产品化 |

另加两条通用合规：用户数据与隐私按当地法规处理；AI 生成内容的标识、版权与平台规则按目标市场要求自行核实。

## 5. 性能与上线门槛（把「优化项」写成「验收项」）

| 项 | 门槛 | 依据 |
|---|---|---|
| 首字 / 首图响应、P95 延迟 | 写进验收标准（例如 P95 < 3s，按你的场景定） | 有搜索产品单次 >5s，留存崩塌 |
| 扣点正确性 | webhook 重放两次只加一次点数 | 经济层指标 |
| 失败可见 | 任何外部依赖失败都有明确提示 + 日志 | Fallback 工程原则 |
| 成本可见 | 后台能查到「昨日总调用成本 / 单次成本」 | 负收入案例 |
| 回滚 | 保留上一个可部署版本，一键回退 | 成熟团队的「灰度发布 + 回滚预案」 |

> 四层指标看板（获取 / 激活 / 留存 / 经济）里，**经济层最容易被小白漏掉**。哪怕只做一个简单后台页面，也要能看到「今天花了多少引擎费、收了多少钱」。

## 6. 一句话记住

> 骨架让你做得快，**适配器 + Fallback 让你活得久**，**单位经济让你不白干**。
