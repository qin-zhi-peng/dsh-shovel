# 骨架目录结构（哪些永远不动，哪些每次换）

> 这份文件把「共用同一副骨架」那句话变成可执行的目录约定：**「差别只在后面接的引擎与前面的 UI 主题」**。
> ★ = 冻结区（`core/`，只整体升版本）；☆ = 可换区（每次新项目改这里）。

```
my-app/
├── .env.example                 ☆ 从模板复制成 .env.local（不进 Git）
├── .gitignore                   ★ 必须包含 .env.local / node_modules / .next
├── SPEC.md                      ★ 骨架规格（发给 AI 的第一句话）
├── 依赖安装清单.md               ☆ 参考
├── package.json                 ★ 依赖钉死，加包要申请
├── README.md                    ☆ 本次产品说明（一句话 + 怎么跑 + 怎么验）
├── supabase/
│   └── migrations/              ★ 建表 SQL（profiles / orders / generations）
├── src/
│   ├── core/                    ★★ 冻结区：整体升级，不逐文件改
│   │   ├── auth/                # 当前用户、鉴权守卫
│   │   ├── db/                  # 唯一数据库客户端
│   │   ├── credits/             # 冻结 → 成功才扣 → 失败回滚（事务）
│   │   ├── billing/             # webhook 验签（raw body）+ 幂等
│   │   ├── storage/             # R2 上传 / 签名 URL
│   │   ├── fallback/            # runWithFallback：超时 / 重试 / 降级 / 成本阀
│   │   ├── observability/       # 日志、埋点、错误上报、成本记录
│   │   ├── seo/                 # metadata / sitemap / 结构化数据
│   │   └── ui/                  # shadcn 基础组件 + 全站主题变量
│   ├── adapters/                ☆ 每次换：一个能力一个文件
│   │   ├── types.ts             ★ 统一接口 GenInput / GenResult / EngineAdapter（不许改）
│   │   ├── index.ts             ☆ 组装降级链：[primary, secondary, mock]
│   │   ├── openrouter.ts        ☆ 文本/对话
│   │   ├── replicate.ts         ☆ 图像/音视频
│   │   ├── fal.ts               ☆ 备用引擎
│   │   └── mock.ts              ★ 假引擎：零 key 跑通全流程（永远保留）
│   ├── apps/                    ☆ 每次换：本次产品
│   │   └── <topic>/
│   │       ├── page.tsx         # 落地页 + 主交互
│   │       ├── route.ts         # 本次业务 API（鉴权 → 冻结 → 生成 → 扣点 → 留痕）
│   │       └── components/      # 本次专用组件
│   ├── content/                 ☆ 文案 / pSEO 数据 / messages（多语言预留）
│   └── app/                     ★ Next.js 路由壳：layout、全局样式、错误页、sitemap
├── tests/                       ☆ 与本次改动对应的用例
└── templates→ 见方案包 templates/  ★ 管理与验收清单（不随产品变）
```

---

## 职责边界（三条铁律）

| 铁律 | 说明 | 违反的后果 |
|---|---|---|
| `core/` 冻结 | 任何新需求先问「能不能只在 `apps/` / `adapters/` 里实现」 | 骨架被改一次，下个项目就得重新调，复利断掉 |
| 单向依赖 | `apps/ → core/ → adapters/` 的接口；`core/` 不得 import 任何具体实现 | 换引擎要改一堆文件 |
| 厂商 SDK 只在 `adapters/` | 页面/业务代码里不许出现任何 AI、支付、数据库 SDK 的 import | 供应商一变，全线返工 |

---

## 新增一个 AI 能力的正确姿势（4 步）

1. 在 `src/adapters/` 新建 `<name>.ts`，实现 `types.ts` 里的 `EngineAdapter`（`name` / `estimateCost` / `generate`）。
2. 在 `src/adapters/index.ts` 的降级链里插入它，**末尾永远保留 `mock`**。
3. 在 `.env.example` 加对应 key，在 `SPEC.md` §1 不改动的前提下补一行说明。
4. 让它走 `core/fallback/runWithFallback()`，并在 `tests/` 里加「主引擎失败 → 降级 → 不扣点」用例。

**错误姿势**：直接在 `page.tsx` 里 `fetch("https://某厂商/api...")`。这正是很多工具产品的死法——引擎不在自己手里，改版即停摆。

---

## 升级 core/ 的流程（谨慎）

只有「下个项目确实还需要、且属于通用能力」的代码才回写：

1. 从本次项目复制该段代码到 `core/` 对应模块，去掉所有本次产品的硬编码。
2. 补一个 `tests/` 用例，确认 `mock` 链路仍通。
3. `SPEC.md` 版本号 +0.1，并在 changelog（本文件末尾）记一行：日期 / 项目 / 新增了什么 / 下个项目省了哪步。
4. 下一个项目复制骨架后，验证「复制 → 首个可访问页面」耗时是否下降。没下降说明这次回写没价值，回滚。

## 命名约定

- 目录/文件：小写中划线（`run-with-fallback.ts`）；React 组件：`PascalCase.tsx`。
- 引擎名与 `adapters/` 文件名、`generations.adapter` 字段、`PRIMARY_ADAPTER` 环境变量保持一致。
- 业务 API 路径：`/api/<topic>/generate`；支付回调固定 `/api/billing/webhook`。
- 本次产品目录名 `<topic>` 用英文短词（会进 URL 和数据库值），别用中文或空格。
